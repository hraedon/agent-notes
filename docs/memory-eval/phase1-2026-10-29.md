# Memory recall after Plan 027 Phase 1, 2026-10-29

**Status:** Phase 1 exit check against the Phase 0 baseline
(`docs/memory-eval/baseline-2026-10-29.md`). The fixture labels are still the
unreviewed Claude draft, so read every number here as provisional, as in the
baseline.

## What changed in ranking

- **WI-1.3:** `memory search` and `memory recall` now rank a reflection
  0.07 below a fact of equal similarity by default (`--reflections demote`).
  `--reflections mixed` restores pure similarity; `--reflections exclude` drops
  reflections. `score` in the output is still the raw cosine similarity.
- **No score floor.** See "Score floor" below.
- WI-1.1 (dedup gate), WI-1.2 (contradiction warnings), WI-1.4 (size
  warnings) and WI-1.5 (hygiene) don't change ranking.

## Method

- Same fixture (`tests/memory_eval/fixture.jsonl`, 33 queries, 18 projects)
  and runner (`scripts/eval_memory_recall.py --command both`), on mvmcc02,
  read-only, against production.
- All 59 snapshot names
  (`tests/memory_eval/names-snapshot-2026-10-29.json`) were checked active
  first, with SELECT only. None were missing.
- **Before:** the installed CLI, `~/.local/bin/agent-notes` (1.1.1). It
  reproduces the Phase 0 baseline exactly.
- **After:** the branch CLI (`work/027-p1-hygiene`), default flags.
- **Exclude variant:** the branch CLI with `--reflections exclude` appended
  through a wrapper script, `search` only.
- **Penalty and floor sweep:** an in-process script embedded each query once,
  pulled the top 50 rows from the same composed-search SQL, re-ranked them per
  variant, and scored them with the runner's own `score()`/`aggregate()`. Its
  `mixed` row reproduces the baseline exactly, and its 0.07 row reproduces the
  branch CLI's numbers exactly.

- **Exclude regresses badly.** Four queries can only be answered from
  reflections (cert-watch has no facts at all), so hit@5 falls to 0.867.
- **Strictly facts-first** also loses nP@5: an irrelevant fact, such as the
  padding global memory, outranks the only right answer.
- **Every penalty from 0.04 to 0.15 beats the baseline** on every metric.
- **0.07 is the only value that is best on all metrics at once.** With n = 33,
  the plateau matters more than the peak: anything from 0.05 to 0.10 would be
  defensible.

### Score floor (not adopted)

The baseline asked whether a minimum score would stop the single global
memory from padding small projects. In the same sweep:

| Floor | nP@5 | MRR | hit@5 | Relevant names lost from the top 10 |
|---|---|---|---|---|
| none | 0.923 | 0.861 | 0.967 | 0 |
| absolute 0.35 | 0.923 | 0.861 | 0.967 | 0 (no-op) |
| absolute 0.40–0.50 | 0.890 | 0.845 | 0.933 | 1 (q13) |
| absolute 0.60 | 0.807 | 0.838 | 0.900 | 5 |
| relative, top − 0.25 | 0.907 | 0.861 | 0.967 | 1 |
| relative, top − 0.30 | 0.907 | 0.861 | 0.967 | 1 |
| demote 0.05–0.10 + relative 0.25 | 0.923–0.940 | 0.907–0.913 | 1.0 | 1 |

- **A floor can't improve these metrics; it can only remove results.** Any
  padding ranked above a relevant hit scores higher than that hit, so a floor
  that removes the padding removes the hit too.
- q13's correct answer scores 0.38 (it sits below the global padding at
  0.53). So every absolute floor that removes padding also loses q13, and
  every relative floor tried loses at least one relevant name.
- Every floor that does anything regresses the fixture, so none ships. To
  revisit, add queries whose right answer is "nothing", and measure the junk
  rate directly.

0.8 s wall time on an idle host (0.5 s for the report itself), and 1.8 s while

| Finding | Count |

The 15 pairs are the 15 from Plan 027 §1:

- 6 are pairs among four identical `smoke-test-*` rows.
- 9 are between bulk-imported substrate/sf2 spec and plan documents.

They are long documents on one subject, not true duplicates. Linking such a
pair (`memory link A B --kind relates_to`) removes it from later reports.

# Note Entity Contract (Plan 018 WI-1.1)

**Status:** Active 2026-07-09.

**References:** regista Plan 022 (entity generalization), agent-notes Plan 018,

## Purpose

This document is the single source of truth for the `note` entity shape.
Both faces (agent-notes + dossier) reference this contract; no face defines a
divergent copy (the Plan 010 lesson — divergence between faces was invisible
until a cross-face test existed).

## Entity shape

A `note` is a non-workflow entity in regista's generalized entity model
(`entity(kind, id)`). It carries agent knowledge that is not a work item:
memories and reflections. Breadcrumbs are **not** notes — they are workflow
work-items (see Split Decision below).

| Field | Type | Description |
|---|---|---|
| `entity_kind` | `str` | Always `"note"`. |
| `entity_id` | `UUID` | Generated by agent-notes at creation; stable across updates. |
| `note_subtype` | `str` | `"memory"` or `"reflection"`. Carried in every event payload. |
| `body` | `str` | The note text. Full content, not a hash. |
| `name` | `str` | Human-readable identifier (memory name or reflection slug). |
| `attributes` | `dict` | Free-form JSONB metadata (e.g., `gaps_filed_as` for reflections). |
| `links` | `list[dict]` | Typed links to work items, files, or other notes. Each link: `{target_kind, target_id, relationship}`. |
| `provenance` | (event-level) | Canonical author actor (`actor_id`, `actor_kind`, `actor_metadata`), regista producer, and optional signed action-delegation authorization. Carried by the signed event, not the payload. |

## Event lifecycle

Notes are non-workflow entities: they have no state machine, no transitions,
no review gate. Their lifecycle is a simple event log:

| Transition | When | Payload |
|---|---|---|
| `note_filed` | Initial creation. | `{note_subtype, name, body, attributes, links}` |
| `note_updated` | Body or attributes changed. | `{note_subtype, name, body?, attributes?}` |
| `note_superseded` | A new revision replaces this note. | `{superseded_by: entity_id}` |
| `note_deleted` | Soft delete. | `{}` |

The latest event for a note entity represents its current state. A reader
folds the event log (like regista's replay for work-items) to reconstruct the
note's current body, attributes, and active/deleted status.

## Split decision: breadcrumbs vs memories/reflections

**Breadcrumbs stay workflow work-items** (type `breadcrumb` inside the
`canonical` workflow). They have a lifecycle (open → in_progress → in_review
→ done), a review gate, claims, and cross-lineage provenance invariants.
Making them non-workflow notes would discard the lifecycle machinery that
makes them trustworthy.

**Memories and reflections are non-workflow `note` entities.** They have no
state machine — a memory is filed, optionally updated, optionally superseded
by a newer revision, or soft-deleted. There is no "review" or "close" for a
memory; it is knowledge, not work. The `note_subtype` field distinguishes
them:
- `note_subtype="memory"` — a memory (was `memory_type` in the local table).
- `note_subtype="reflection"` — a session reflection (was `memory_type='reflection'`).

## Regista API usage

Notes are written via `regista.append_event` with `entity_kind="note"`:

```python
face.append_note(
    actor,
    entity_id=note_uuid,
    transition="note_filed",
    payload={
        "note_subtype": "memory",
        "name": "how-deploy-works",
        "body": "Deploy runs in three stages...",
        "attributes": {},
        "links": [
            {"target_kind": "work_item", "target_id": "WI-042", "relationship": "references"},
        ],
    },
)
```

Events are read via `regista.read_events(work_item_id=note_uuid)` (the
`work_item_id` parameter is the entity_id for non-work-item entities).

## Local projection (agent-notes)

The local `memories` table (Postgres + pgvector) is a **projection** of the
signed note entities, exactly as `work_items` is a projection of regista
work-items. The `regista_note_id UUID` column tracks the regista entity_id.

- **Write path (flag on):** write the signed note entity to regista → mirror
  into the local `memories` table (body, attributes, embedding).
- **Write path (flag off):** local-only (legacy path, unchanged).
- **Reconcile path:** offline appends are replayed into regista when the face
  reconnects, mirroring the breadcrumb reconcile path.
- **pgvector rebuild:** the embedding index rebuilds from the note entities by
  reading the latest `note_filed`/`note_updated` event for each entity,
  re-embedding the body, and upserting into the local `memories` table.

## Embeddings are a projection, not the record

pgvector search stays the agent face's private index; the human face (dossier)
reads the signed entities, never the projection. The embedding is computed
from the note body at write time and recomputed on rebuild. It is never
stored in regista — regista holds the signed text; the vector is a local
optimization for semantic search.

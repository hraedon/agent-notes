## Problem

The `start` skill (`~/.claude/skills/start/SKILL.md`) assumes `agent-notes` CLI is globally installed, on `PATH`, and configured with a working `AGENT_NOTES_DSN`. It instructs the agent to run three parallel lookups:

```
agent-notes workspace list --json
agent-notes breadcrumb find --path <repo-path> --status open --limit 10 --json
agent-notes memory list --path <repo-path> --json
agent-notes memory get <name> --path <repo-path> --json
```

When any of these fail, the skill says: "If `agent-notes` exits non-zero or its JSON shape doesn't match what this skill expects, the CLI contract has drifted — file a breadcrumb under project agent-notes."

But the failure mode isn't always contract drift. In practice, on the regista project (`/projects/regista`), the agent hit three distinct layers of failure:

### Layer 1 — CLI not on PATH

`agent-notes` is installed in `/projects/agent-notes/.venv/bin/agent-notes`, not on the system PATH. Running bare `agent-notes` returns "not found". The skill doesn't mention this requirement or offer a fallback.

### Layer 2 — Missing environment variable

Even with the full path, `agent-notes workspace list --json` crashes with:

```
RuntimeError: AGENT_NOTES_DSN environment variable is not set.
Example: postgresql://user:pass@localhost/agent_notes
```

The skill doesn't mention this prerequisite.

### Layer 3 — Project not registered

Projects must be registered via `agent-notes init <path>` before breadcrumb/memory commands work against them. The regista project uses its own on-disk breadcrumb system (`/projects/regista/breadcrumbs/`) and was never registered with agent-notes. Even if layers 1 and 2 were resolved, `breadcrumb find --path /projects/regista` would return nothing.

## What the agent actually did

The agent fell back to manual orientation using available tools:

1. `read /projects/regista` — directory listing
2. `git-constellation_repo_status` — branch/state across repos
3. `git-constellation_recent_commits --days 14` — recent activity
4. `read breadcrumbs/README.md` — open breadcrumbs (regista's own system)
5. `read .regista/worklog.md` — session log (regista's own system)
6. `read .regista/reflections/` — prior reflections (regista's own system)

This worked fine — the regista project has its own breadcrumb, worklog, and reflection infrastructure that predates agent-notes. But the skill added zero value and cost one failed tool call.

## Impact

- The `start` skill is effectively a no-op for any project that hasn't been onboarded into agent-notes. The agent loses time on a failing tool call, then has to rediscover the project's own orientation mechanisms.
- The skill's "file a breadcrumb" instruction on failure creates noise — the CLI not existing isn't a contract drift, it's a missing prerequisite.
- Projects with their own breadcrumb/memory systems (regista has 90+ resolved breadcrumbs, 64 reflections, and a structured worklog) have all the data the skill wants, just in different locations.

## Suggested fixes

**Option A — Graceful degradation in the skill:**

Add a preamble to the skill:

```
Before running agent-notes commands, verify the CLI is available:
  1. Check `which agent-notes` or try the full path `<repo>/.venv/bin/agent-notes`
  2. Check `echo $AGENT_NOTES_DSN` is set

If either check fails, fall back to reading the project's own orientation files:
  - breadcrumbs/README.md (open items)
  - .regista/worklog.md or .agent/worklog.md (session log)
  - .regista/reflections/ or .agent/reflections/ (handoff notes)
  - AGENTS.md (project conventions)

Do NOT file a breadcrumb for missing prerequisites — only for actual CLI contract drift.
```

**Option B — PATH/install integration:**

Make `agent-notes` available globally (e.g., `pipx install`, symlink in `/usr/local/bin/`, or `install-skills` that also sets up PATH). This is a larger change and doesn't help projects that use their own systems.

**Option C — Hybrid approach:**

The skill should detect what's available and use the richest source. If `agent-notes` works, use it. If the project has its own breadcrumbs/worklog/reflections, use those. If neither, say so plainly.

Option C is the most robust. The skill's value is orientation, not the specific tool used to achieve it.

## Files

- Skill: `~/.claude/skills/start/SKILL.md`
- CLI: `/projects/agent-notes/.venv/bin/agent-notes`

## Reproduction

1. Open a session in any project that hasn't been registered with `agent-notes init`.
2. Invoke the `start` skill (or say `/start`).
3. Observe: `agent-notes` commands fail, agent falls back to manual reads, skill adds no value.

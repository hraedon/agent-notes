## Resolution

### Part 1 — `find_breadcrumbs` SQL parameter binding mismatch

Fixed in `src/agent_notes/servers/breadcrumbs_model.py` (`find_breadcrumbs`):
- The query had 5 placeholders (`%s`) but only 4 parameters because the `ORDER BY b.embedding <=> %s` placeholder was appended to the SQL twice but only one parameter was added to the Python `params` list.
- Corrected the param ordering: the `SELECT distance` placeholder consumes `query_vec` first; then WHERE conditions are appended; then `ORDER BY` consumes the second `query_vec`; finally `LIMIT` is added.
- Also added `%s::vector` explicit casts (copying the pattern from `suggest_duplicates`) so PostgreSQL's operator resolution doesn't fall back to `smallint[]` or `double precision[]`.

Regression test added: `test_find_breadcrumbs_parametric` in `tests/test_breadcrumbs.py` exercises (`project` set/unset) × (different queries) to ensure no parameter mismatch error is raised.

### Part 2 — `query_breadcrumbs` empty results for projects with known breadcrumbs

The empty results were a secondary effect of BC-006: substrate's project row in the DB had no `breadcrumbs_dir` configured, meaning breadcrumbs filed via MCP had their projections silently written to `/tmp/active/`. The DB rows existed, but the human-visible on-disk index lived elsewhere.

With BC-006 fixed (`_write_projection` now refuses when `breadcrumbs_dir` is unset) and `agent-notes init` available to register projects with their on-disk path, new projects will be correctly configured before breadcrumbs are filed. Existing unconfigured projects can be remediated by running `agent-notes init <path>`.

The `is_open=true` filter itself (mapping to `closed_at IS NULL`) was already correct and is covered by `test_query_open_filter`.

## Observed (historical)

Two related read-side failures encountered while searching the substrate project for existing breadcrumbs before filing BC-197.

### 1. `find_breadcrumbs` — SQL parameter binding mismatch

Call:

    mcp__breadcrumb__find_breadcrumbs(
        workspace="default",
        project="substrate",
        query="delegation chain on-behalf-of human principal agent actor",
        limit=5,
    )

Response:

    Error: the query has 5 placeholders but 4 parameters were passed

Reproduced with a second call dropping the `project` parameter:

    mcp__breadcrumb__find_breadcrumbs(
        workspace="default",
        query="multiple signers impersonation user identity",
        limit=5,
    )

Response:

    Error: the query has 4 placeholders but 3 parameters were passed

### 2. `query_breadcrumbs` — empty results for project with known breadcrumbs

Call:

    mcp__breadcrumb__query_breadcrumbs(
        workspace="default",
        project="substrate",
        is_open=true,
        limit=5,
    )

Response:

    No breadcrumbs found.

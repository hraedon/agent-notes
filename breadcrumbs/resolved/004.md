title: ToolRegistry.merge dedupes tools but appends resource handlers without dedupe
---
`ToolRegistry.merge` (src/agent_notes/core/mcp.py:69) dedupes the _tools/_fns half but unconditionally extends _resource_handlers. Latent today (kind URI prefixes are distinct: note://breadcrumb/, note://memory/), but every Server.__init__ runs _register_core_tools on each kind subclass before merge. If any core-level resource handler is added in the future (e.g., note://workspace/), it'll be registered N times in omnibus mode, producing duplicated resources/list output.

The asymmetry between tools (dedupe) and resource handlers (append) is the kind of subtle bug that costs an afternoon. Fix at the same time as BC-001 — same merge function. Mirror tool-dedupe semantics for resource handlers (dedupe by prefix, or raise — match whatever BC-001 chooses).

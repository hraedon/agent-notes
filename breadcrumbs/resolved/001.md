title: Omnibus tool-name collisions are silently first-wins, contradicting cli.py
  docstring
---
`ToolRegistry.merge` (src/agent_notes/core/mcp.py:69) drops same-named tools from later registries (`if name not in self._fns`), but cli.py:32 docstring claims "last wins." `BreadcrumbServer` and `MemoryServer` both register `trace_graph`; in `main_omnibus` breadcrumbs mounts first, so memory's `trace_graph` is silently shadowed.

Today this is invisible because cross-kind callers use `trace_graph_all` in the search server, and core tools (add_link, list_workspaces, etc.) are functionally identical. But the next disagreeing pair will silently misbehave.

Fix options: (1) namespace per-kind tools on collision, (2) raise on collision (preferred — explicit), or (3) keep first-wins but fix the docstring and add a logger.warning. Add regression test that mounts breadcrumbs+memory and asserts both trace_graph variants reachable.

## On the project

The work_item subpackage split (Plan 016) is architecturally sound — the facade dispatch pattern is clean and the module boundaries match the plan. However, the move from a monolith to separate `_regista`/`_native` modules surfaced several pre-existing bugs that were hidden by the single-file layout: `force` was never threaded to the regista path, delete didn't clean up leases, and routing decisions were based on face presence rather than item mapping. These are the kind of bugs that a refactor *should* catch, and the adversarial review process is what actually caught them.

The gate-integrity system (verifier.py) is the most security-critical piece in the codebase. The reviewers found several theoretical bypass vectors — some are real (direct terminal creation), some are architectural risks (hybrid regista/native items). The system needs more adversarial testing before it can be considered production-hardened.

## On the work done

**What went well:** The four-reviewer parallel approach caught bugs that a single pass would have missed. The Kimi reviewer found the `force` silent-drop (CRITICAL) and the FK violation on delete. The GLM reviewer found the `_load_json` silent data loss. The Nemotron reviewer found the `load_public_key` path traversal. The Minimax reviewer identified the missing test coverage gaps.

**What I'm confident in:** The force-close routing fix, the lease cleanup fix, the idempotent filing terminal-state guard, the `_load_json` error raising, the `load_public_key` validation, and the `attest_gate_waiver` actor_id fix are all straightforward, well-tested, and clearly correct.

**What I'd want a second pair of eyes on:** The `delete_work_item` routing change — I added a `_queries.get_work_item()` call before deciding the path, which means an extra DB round-trip. The `_load_json` error handling wraps both install and uninstall paths, but the `RuntimeError` propagation through `_install_harness_one` and `_uninstall_one` should be tested explicitly.

## On what remains

- **WI-021 (new):** Soft-delete tombstone not honored by `fold_all_work_items` — this is the most important remaining issue. It means deleted items can be resurrected by a rebuild. Needs a real tombstone in the fold logic.
- **WI-020 (new):** Native deferred `close_work_item` is non-atomic — two separate transactions. Not catastrophic (item ends up in a valid state) but violates the atomicity contract.
- **WI-019 (existing):** `--json` stdout corruption from regista structlog lines — still open, affects the new review-transition CLI commands too.
- **BC-027 (existing):** Native lease ops skip `change_log` — audit trail gap on the degrade path.
- **Reviewer findings not filed:** The verifier's gate-integrity bypass via direct terminal creation, the concurrent lamport transition loss, and the hybrid-item false positives are all worth filing if the gate-integrity feature is going to be relied upon.
- **Stale branches:** `error-contract-completion`, `feat/breadcrumb-git-reconcile`, `plan-004-phase-9d-mcp-removal`, `plan-007-implementation` are all merged to main and can be deleted. Two locked worktrees exist.

## Gaps to flag

- `work_item_model.py:332-336`: The `delete_work_item` routing now does a `get_work_item` lookup before deciding the path — this is an N+1 concern if delete is called in bulk. Consider caching or a single-query approach.
- `_native.py:298-336`: `close_work_item_native_deferred` calls `update_work_item` twice, each opening its own connection. The non-atomicity is filed as WI-020 but worth flagging here.
- `verifier.py:622-625`: The `_check_degraded_completion` "no transitions" branch treats direct-terminal-creation as a dismissal. This is a gate bypass — an item created directly in `done` state passes the detector. Not filed as a work item yet.
- `harness.py:290`: `_load_json` now raises `RuntimeError` on parse errors, but `_uninstall_one` also calls it — if the manifest is corrupted, uninstall will fail rather than cleaning up what it can.
- `regista_face.py:313-318`: `_amend_transition_for` raises on terminal states, which was the root cause of the idempotent filing crash. The fix in `_regista.py` catches this case, but the error message in `_amend_transition_for` could be more helpful by suggesting the caller skip the amend.
- The repo is now public. The CI config references `github.com/hraedon/regista.git@main` — ensure regista is also public or the CI will break for external contributors.

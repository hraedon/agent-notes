## On the project

The kernel is genuinely solid. The op-CRDT model (op_log + content_blobs + fold into work_items) is clean, the status lattice is fail-safe, and the Tier A degrade contract (coordinator-absent / local-lease) is the right default posture. The migration was the acid test: 548 rows, 862 ops, and the cache rebuilt byte-for-state from the op-log alone. That's the invariant the plan promised, and it holds.

One thing that will bite: the `breadcrumbs` table is still present as a safety net. The `orient` command was still querying it until I fixed it this session. Other code paths probably still reference it — the reconcile command, the breadcrumb CLI verbs, the `doctor` links audit. The dual-table state is a real risk for drift, not just confusion. After a week of burn-in, someone should drop `breadcrumbs` and retire `BreadcrumbModel` entirely.

## On the work done

The migration script had three bugs I had to fix live: (1) incomplete status mapping — 8 bc_status values (`implemented`, `proposed`, `obsolete`, `rejected`, `accepted`, `active`, `decision-pending`, `deferred`) were falling through to "open" instead of mapping to their correct terminal/active work-item statuses; (2) missing `entity_id` column in the close/defer op INSERT; (3) no handling for `deferred` items needing a `set_status` op instead of a `close` op. The first run hit the NOT NULL violation on entity_id and rolled back cleanly (psycopg autocommit behavior saved us — the first 4 rows weren't committed). After fixes, all 548 migrated successfully.

The orient bug was a near-miss: the opencode plugin was loading correctly but injecting stale data from the breadcrumbs table into every session's system prompt. Every future session would have seen ghost open items. Catching it before the harness restart was important.

- `src/agent_notes/cli/orient.py:63` — the JSON key is still `open_breadcrumbs` even though it now returns work items. The opencode plugin's `formatOrientPayload` matches this key, so changing it requires coordinating both. Low priority but semantically wrong.
- `~/.config/opencode/opencode.json:5` — the agent-notes plugin path points to `/projects/agent-notes/integrations/opencode/index.js` (source), not a built/dist copy. If the source is moved or edited, the plugin breaks silently. The agent-provenance and agent-wake plugins use `dist/` — agent-notes should too.
- The `agent-notes work-item update --status deferred` command doesn't seem to add a `set_status` op to the op_log — it appears to update the cache directly. If the cache is rebuilt from the op-log, deferred items may revert to their create-op status. This needs verification.

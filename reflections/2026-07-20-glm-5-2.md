# Session Reflection — 2026-07-20

**Work summary:** Ratified WI-021 (dry-run exit-0 convention) via the cross-lineage adversarial review gate, then discovered and fixed the root cause of the gate friction: agent-notes' `file`/`update`/`close` CLI commands had no `--model-lineage` flag, so agent authors could only declare lineage via env var. Added the flags, threaded `model_lineage` through the model layer to both regista and native paths, renamed `reviewer_actor` → `actor_with_overrides` with a `clear_principal` kwarg, and ran 3 rounds of cross-lineage adversarial review (Kimi → Nemotron → Minimax) with no major findings remaining.

---

## On the project

The three-component architecture (agent-notes / regista / dossier) is well-factored. The cross-lineage review gate is a genuinely interesting design — it enforces that no agent lineage can self-review, using signed event history as the sole source of truth. The weakness exposed today wasn't in the gate itself but in the *input path*: the CLI gave authors no way to declare their lineage per-call, only via env var. When the env wasn't set (common for subagents invoked by skills), the author's lineage was silently undeclared, and the gate correctly fail-closed — but the error message ("undeclared agent author") didn't point the user to the fix. The fix is small and clean; the architecture held up well.

## On the work done

The change is 7 files, +308/-32 lines. The core insight — that `reviewer_actor` was already general enough for authors, just misnamed and with wrong principal-clearing semantics — kept the diff small. The `clear_principal` kwarg is the right abstraction: reviewers clear principal (separation of duties), authors preserve it (provenance chain).

The adversarial review process caught real issues. Round 1 (Kimi) found 3 MAJOR bugs I'd shipped: native `update_work_item` silently dropped `model_lineage`, native close path dropped it entirely, and `actor_with_overrides` cleared `principal_id` for authors (breaking multi-user attribution). All three were genuine — the kind of thing that looks correct in isolation but fails in production. Round 2 (Nemotron) verified the fixes and caught a null-in-payload MINOR. Round 3 (Minimax) confirmed clean. This is the process working as designed.

What I'm confident in: the regista path is correct and well-tested. The `clear_principal` semantics are verified by 4 unit tests. The fail-closed behavior is preserved by an explicit regression test.

What I'd want a second pair of eyes on: the native path's `model_lineage` in the op-log payload is stored but never read back by anything. The native review gate stores review notes in `diagnostic_keys` but doesn't actually check author lineages (it can't — the gate doesn't run off-regista). So the `model_lineage` in the native op-log is purely for provenance/audit, not for gate enforcement. That's fine, but it's a different contract than the regista path and worth documenting.

## Gaps to flag

- **Native op-log `model_lineage` is write-only** — stored in the create/update/close payloads but never read back or surfaced in `diagnose` output. If someone needs to verify author lineage in degrade mode, they'd have to parse the op-log JSONB directly. (`_native.py:81`, `_native.py:191`, `_native.py:374`)
- **`model_lineage` has no validation** — any string is accepted. A typo like `--model-lineage kim` will be stored and silently fail at review time with a confusing lineage-collision error. An allowlist or at least lowercase normalization would help. (`face_factory.py:168-169`)
- **Idempotency-guard amend path** — when `file_work_item` finds an existing item and amends it, the `model_lineage` is passed via `actor_with_overrides` but the amend path uses `face.amend_breadcrumb(actor, ...)` which passes `actor_metadata` to regista. This should work, but it's not tested. (`_regista.py:72-82`)
- **`reviewer_actor` deprecation** — the alias is marked deprecated but has no removal timeline. If it's intended to stay as a convenience alias, the deprecation notice should be removed. If it's going away, a timeline should be set.

## On the project

The agent-suite blueprint is a genuinely coherent target, and Plan 017's slice of it (agent-notes as the "agent face") is well-scoped: read shared config, install repeatably, report health in the common shape, finish the cutover. WI-1.1/WI-2.1/WI-3.1/WI-2.2 were already done; this session closed WI-4.1, which was the item the last reflection explicitly flagged as *blocked by regista Plan 025*. regista shipped `_secrets.py` (resolver) + `_config.py` + `_provision.py` since then, so the blocker was real and is now genuinely gone.

The most pleasant discovery: regista's `KeySet._load` already resolves per-key `secret_ref` from the backend (`_keys.py:139-152`). So the signing *manifest* need not contain secrets — it can hold only pointers, and the raw key material lives in Vault/AKV. That made WI-4.1's key half much cleaner than I first feared: I only had to support a *manifest* ref (materialize to a temp file), not invent key custody from scratch. The custody contract is really regista's; agent-notes is a thin consumer.

The codebase's separation of concerns continues to pay off. Wiring secret resolution into three places (config.resolve_dsn, face_factory._build_face, doctor) touched small, well-named seams — no god-objects to refactor.

## On the work done

**What went well:** The "literal-safe passthrough" design held up exactly as intended — a literal DSN (`postgresql://...`) has no provider prefix, so it returns unchanged and regista is never imported for the common case. Zero regression risk, and the test suite confirmed it (DSNs with `@`/`:` in the password pass through byte-identical). The two-reviewer convergence on the findings was strong — both independently flagged the same BLOCKING hole (DSN silent-literal-fallback) and the same MAJORs (`__cause__` leak, `akv:` phantom, case-sensitivity, explicit-arg bypass, doctor not resolving the DSN). That convergence is the signal that those were real, not nitpicks.

**What I'm most glad I caught:** the silent-literal-fallback trap. regista's `_detect_prefix`, when it sees a prefix that isn't a *registered* provider (e.g. `vault:` with hvac absent), falls back to `literal` and returns the ref *string* as the bytes. For the manifest path I'd already added JSON-shape validation that catches it; for the DSN path I had NOT, and both reviewers correctly called that BLOCKING — a `vault:` DSN with hvac absent would have silently become the literal string `"vault:..."` handed to psycopg, and the doctor's `secrets_backend` check would have *passed* (false positive) while the store was unreachable. The post-resolve guard (`result == normalized` for a `_REMOTE_PROVIDERS` prefix) closes it.

**Where I'm less sure / would want a second lineage's eyes:**
- The `_REMOTE_PROVIDERS = {vault, azure}` scoping. Round-2 caught that I'd initially included `env`, which would have false-positived on a self-referential `env:VAR` whose value is the string `env:VAR` AND emitted a wrong "install regista[env]" message. `env`/`file` are always registered so they can never silently fall back — removing them from the guard set was clearly right. But the guard itself is a heuristic comparing strings; I'd value a cryptographer's confirmation that there's no provider I've misclassified.
- The `from None` decision. Round-1 *recommended* it (suppress `__cause__` to keep regista's ref-echoing exception messages out of logged tracebacks); I agreed and applied it; round-2 flagged it as a debuggability trade-off. It is a real trade — I documented it in the module docstring as security-over-debuggability, but a deployment that prioritizes operator debuggability over secret-ref confidentiality might want a config knob. I did not add one.
- Windows runtime validation. I code-reviewed the Windows paths (`mkstemp` honors `%TEMP%`; `chmod 0o600` is POSIX-only and a no-op on Windows where the file is already owner-scoped) but could not run a real Windows profile. That's an honest deferral, documented in the plan log.

## Gaps to flag

- **`resolve_dsn` guard is a string-compare heuristic, not a crypto property.** `result == normalized` for a `_REMOTE_PROVIDERS` prefix catches the documented silent-fallback, but a Vault secret whose value *legitimately* equals its own ref string would false-positive. Pathological, but worth knowing the guard is structural, not cryptographic (`core/secrets.py:163`).
- **`__cause__` suppression is load-bearing for the secret-safety claim.** If a future contributor reverts `from None` to `from exc` "for better tracebacks," they reintroduce the ref-leak vector. There's a comment, but no test asserts `__cause__ is None` for the manifest path (only the DSN path is tested) (`tests/test_secrets.py`).
- **`file:` manifest existence is deferred to regista's KeySet at face-build, not at config resolution.** Consistent with bare-path behavior, but means a typo in `REGISTA_KEY_PATH=file:/wrong` surfaces as a KeySet load error at first write, not at `doctor`/config time — except the doctor's `secrets_backend` check *does* stat it now, so `doctor --json` catches it before the write path. The asymmetry (doctor catches it, runtime defers it) is mild but real.
- **The native `AGENT_NOTES_DSN` is now routed through the resolver too** — a scope expansion beyond WI-4.1's literal text (which scopes to the regista DSN). It's literal-safe and useful (the native store has the same custody concern), and I documented it in the plan log, but it is a behavior change to a hot path that a reviewer should be aware of (`core/config.py:128`).
- **`akv:` is silently treated as a non-ref** (literal) now that it's removed from `_ALL_PROVIDERS`. An operator following the *blueprint* (which says `akv:`) will get a confusing connection error rather than a clear "use azure:." The right fix is upstream (regista adds `akv`, or the blueprint corrects to `azure:`); agent-notes documents `azure:` in the install doc, but the blueprint/blueprint-vs-regista mismatch is unresolved.
- **Round-2 flagged test coupling to private `_FACE_CLEANUPS`** (`tests/test_secrets.py` `test_face_reset_scrubs_real_temp_manifest`). It directly pokes the private dict. Acceptable for a lifecycle test, but brittle if the cleanup-tracking implementation changes.

## On the project

agent-notes has grown into a dense but well-structured system. The op-CRDT work-log kernel, the dual-path (regista vs. native) write model, and the projection mirror are coherent — the Plan documents are doing real work as the architectural source of truth. The main pain is exactly what Plan 013 diagnosed: the status vocabulary was declared in 6+ places with no compile-time or test signal catching drift. Each surface was "obviously correct" in isolation. The fix (lifecycle.py + consistency guards) is the right shape — it doesn't unify the three layers (YAML, DB vocab, code module) but reconciles them by test, which is honest.

The dual-path divergence (regista path enforces transitions; native path didn't) is now closed for vocabulary (WI-1–4) and for transitions (WI-5). The semantic divergence (close → review gate vs. terminal close) is correctly left for a future plan.

## On the work done

**What went well:** The extraction was mechanical and clean. The lifecycle module is a leaf with no imports from the consumers it serves, so there's no circular import risk. The consistency guards are comprehensive — they check the DB CHECK constraint, the wi_status vocab, the workflow YAML, the projection map, the regista face terminal set, and the bc_files flags. The adversarial review caught a real production breakage (C1: bc_files fallback) that the test suite missed because no test exercised an unknown on-disk status.

**What I'm confident in:** The lattice rank table (§5). The fail-safe ordering (open > in_progress == blocked > in_review > in_human_review > claimed > deferred > done == closed) is correct per the plan's rationale. The `claimed` placement at rank 4 — below active lifecycle states, above terminal — is the right call: a lease should not override real lifecycle progress, but it also should not be silently completed.

**What I'd want a second pair of eyes on:** The WI-5 transition pre-flight on the native path is a behavior change — previously, the native path accepted any vocab-valid status with no transition check. Now it rejects illegal transitions. The `force=True` escape hatch is wired into the CLI (`--force`) and the reconcile command (auto-force). But there may be callers (scripts, other harnesses) that rely on the old permissive behavior and will now get ValueErrors. The plan acknowledges this is the highest-risk change.

**The `claimed` vs `deferred` ranking surprised me initially** — I wrote a test asserting `deferred` wins, but `claimed` (rank 4) actually beats `deferred` (rank 2). The rationale: a lease (potentially active) is more "unfinished" than a deliberate park. The adversarial reviewer also got this backwards in their analysis. The test now correctly asserts `claimed` wins.

## On what remains

- **WI-018** (CLI affordance for canonical lifecycle transitions) is partially addressed by WI-5's `--force` flag but remains open — it's about a broader CLI surface for driving lifecycle transitions explicitly.
- **The semantic dual-path divergence** (close → review gate vs. terminal close) is intentionally out of scope for Plan 013 and belongs in a separate plan.
- **Repair of already-mis-resolved items**: Plan 013 §8 records the decision to accept "no repair pass" for historical damage from the P0 bug. If a discrepancy surfaces, the op-log retains the raw ops for forensic recovery.
- **The `regista_face._TERMINAL_STATES`** is intentionally `{"done"}` (not `{"done", "closed"}`) because the regista path only produces canonical states. A consistency guard now verifies it's a subset of `lifecycle.IS_TERMINAL`, but it's not derived from lifecycle — that would be a behavior change (blocking amendment of `closed` items on the regista path, which currently doesn't happen but might be correct).

## Gaps to flag

- **`bc_files._STATUS_FLAGS`** (`src/agent_notes/core/bc_files.py:22`) still duplicates lifecycle truth for non-canonical statuses like `"stabilized"`, `"new"`, `"proposed"`. A consistency guard checks overlap with lifecycle, but the dict itself is hand-maintained and could drift for non-overlapping entries. Consider deriving canonical entries from lifecycle in a future pass.
- **The `close` op type** in `kernel._resolve_status_lattice` always resolves to `"closed"` (rank 0). There's no transition check on the native `close_work_item` path — any state can be closed. This is pre-existing behavior and the plan doesn't ask to change it, but it means the native path can still create an "illegal" close (e.g., closing an `in_progress` item without going through the review gate). WI-5 only covers `set_status` ops, not `close` ops.
- **The exit code for transition rejections** in `cli/breadcrumbs.py:155` and `cli/work_items.py:137` returns `EXIT_NOT_FOUND` for all ValueErrors, including transition rejections. A `EXIT_CONFLICT` would be more appropriate, but this is pre-existing behavior.
- **No test for the CLI `--force` flag end-to-end** — the `TestTransitionPreFlight` tests cover the model layer, but there's no test that passes `--force` through the argparse layer to the model. The wiring is simple (`getattr(args, "force", False)`) but untested.

## On the project

The constellation model (sibling repos under a common parent) is clean and the test surface is genuinely strong — 609 integration tests against a real Postgres container, not mocks, which is the right call for trigger/CTE/change_log semantics. The dual-path architecture (native op-log as degrade fallback, regista as SoT) reads coherently after the Plan 014 work from the earlier session today.

The systemic weakness this session surfaced is tooling drift, not architecture: `make lint`/`make test` were broken and nobody noticed, because the `.venv` had regista editable-installed by hand, so direct invocation (`.venv/bin/ruff`, `.venv/bin/pytest`) masked the fact that `uv run` re-resolution failed and the lockfile didn't contain regista at all (0 occurrences). The lockfile and the venv had diverged from reality. This is exactly the kind of gap that a "CI is green" assumption hides — if CI runs `make lint` via `uv run`, it would have been failing; if CI doesn't, then committed lint errors (the 4 in the dedup script) slipped through uncaught. Either way the build contract wasn't being enforced.

## On the work done

The `[tool.uv.sources]` fix is the piece I'm most confident in — it's the documented uv idiom for local path dependencies, it makes `uv lock` reproducible (regista v0.5.0 + transitive deps now pinned), and `make lint`/`make test` resolve from a clean state. `editable = true` is correct: it matches the existing venv state and means live edits to regista reflect immediately during development, which is how this constellation is meant to work.

What I'd want a second pair of eyes on: the relative-path assumption (`../regista`). It's safe given the constellation layout invariant (every repo is a sibling under `/projects/`), but it's an implicit contract — a contributor who checks out agent-notes alone gets a resolution failure rather than a helpful "install regista here" message. The comment I added documents it, which is the best you can do without a workspace (and a workspace is wrong here since regista is independently versioned/released).

The lint fixes were trivial (ambiguous `l` → `loser`, line-length wrap, import sort). The isort result left slightly awkward blank-line-separated inline imports inside the function body, but it's a one-off maintenance script, not worth hand-tuning.

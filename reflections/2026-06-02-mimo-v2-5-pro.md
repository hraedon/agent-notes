# Session Reflection — 2026-06-02

**Work summary:** Resolved 7 breadcrumbs across medium and low severity. Fixed doctor embedding model loading, breadcrumb sync YAML parsing, web app SQL duplication, stale MCP harness detection, workspace error messages, and HF Hub output noise.

---

## On the project

agent-notes is well-structured for a CLI-first tool. The model layer separation (BreadcrumbModel, memory_model) makes it straightforward to deduplicate code. The breadcrumb system itself is a good forcing function for tracking work — having 22 open breadcrumbs at session start gave clear direction.

The embedding singleton pattern is clean but the 270MB model load on every doctor invocation was a real UX problem. The fix (opt-in via --check-embed) preserves the capability while defaulting to fast.

## On the work done

The medium-severity issues were the most impactful:
- BC-014 (doctor embedding) was a quick win with high agent-UX payoff
- BC-021 (YAML parsing) was a correctness bug — silent data loss is worse than a crash
- BC-020 (web app dedup) reduced maintenance surface meaningfully

The low-severity fixes (BC-015, BC-023) were noise reduction. BC-013 (harness stale entries) is forward-looking — the next rename or MCP removal won't silently leave dead config entries.

One concern: BC-022 (breadcrumb get returning empty fields) couldn't be reproduced from the code. The get_breadcrumb method uses SELECT * which should return all fields. The issue may be project-specific or already fixed by a prior schema change. Left it open for the user to verify.

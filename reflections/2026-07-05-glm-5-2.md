## On the project

The publication-gate architecture is well-designed: the denylist is never
committed (gitignored), supplied via env var or CI secret, and the committed
script (`check_committed_identifiers.py`) carries no identifiers. The
layered design (pre-commit hook as early warning, CI as hard gate) is sound.
The adcs-lens WI-010 lesson — that the scrub must cover ALL identifier forms,
not just hostnames — was the key insight that drove the denylist expansion.
The agent-notes repo is clean of all identifier forms in its tracked tree;
the only leak is in git history (the personal email in a deleted file and as
author/committer identity).

valid concern, but the bare command is the cross-platform correct choice;
Claude Code's hook executor handles non-zero exits. Three tests were
hardcoded with `/dev/null` (POSIX-only) — fixed to `os.devnull`.

The pre-existing vault test failure (regista version mismatch) was a
drive-by fix: the test expected the silent-literal-fallback message but the
installed regista raises `RegistaError` directly. Fixed to accept both

## Gaps to flag

- **`cli/__init__.py` hook failure semantics:** dropping `|| true` means
  non-zero exits from `agent-notes orient` (e.g. `EXIT_NOT_CONFIGURED` on a
  fresh clone) are no longer silently swallowed. Claude Code's hook executor
  is assumed to handle this gracefully, but this is unverified — if it
  blocks on non-zero, the orient hook will break sessions on unregistered
  projects. `cli/__init__.py:51,84`.
- **`os.replace` on Windows:** `harness.py:200` and `outbox.py:181` use
  `os.replace` which can raise `PermissionError` on Windows if the target
  file is held open by a running process. Not a code defect but an
  operator-experience footgun on Windows.
- **XDG paths on Windows:** the suite uses `~/.config/` throughout
  (`config.py`, `envelope.py`, `verifier.py`, `outbox.py`), which is
  functional but non-conventional on Windows (prefers `%APPDATA%`).
  Deliberate design choice, consistent across all files.
- **`uv.lock` changed:** regista now has a `windows` extra in its
  `provides-extras`. This is from the dirty regista repo (8 files changed).
  The lock file change is legitimate but the regista changes are uncommitted.

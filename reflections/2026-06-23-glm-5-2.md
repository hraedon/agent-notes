## On the project

The convergence bet — collapse agent-notes' op_log engine onto regista as the one
authoritative store, with agent-notes as the agent/CLI face — is sound and the
seams landed cleanly. The foundation (`RegistaFace` as an Actor-injected choke
point mirroring dossier's `RegistaGateway`, `face_factory` selecting plain vs
outbox-aware, `projection.py` as the single regista→local mirror) is the right
shape: regista is authority, the local `work_items` table is an honest search
projection, and the write path is gated so the legacy op_log path is byte-for-byte
unchanged when the flag is off. The plan doc (`plans/009`) earns its keep as the
canonical reference — every review finding traced back to a §-numbered decision.

The part I'm least sold on: breadcrumbs-as-work-items already happened (the
`breadcrumbs` table was dropped in Tier A), so "breadcrumb→regista-work-item
migration" is really "work_items→regista migration," and the migration reproduces
only the **final** state (one transition from open), not full lifecycle history.
That's a fidelity limit I accepted (D8) but it means regista's chain going forward
is authoritative while the pre-migration op_log holds the rich history — a split
that will surprise someone eventually.

## On the work done

The player-coach model (kimi/glm implement, nemotron reviews) caught real issues
both rounds: the `list()` single-page cap that silently broke rebuild >100 items;
`amend_breadcrumb` trusting stale local state; migration idempotency; the JS
`typeof null === "object"` crash; the over-broad `_TRANSPORT_ERRORS`. Worth keeping.

What I'm confident in: the AC-1/2/3 InMemory tests (the gate) are solid — the
outbox never swallows business errors, hand-edits are rejected loudly, conflicts
block. The reconcile ordering (apply→remove→clear) is correct and the reviewer's
"fix" would have introduced duplicate-create risk; I verified it and held the line.

What I'd want a second pair of eyes on: the enforcement-hook choice to auto-run
`outbox reconcile` on every opencode compaction and Claude Stop. It's safe (reconcile
removes an op only after regista accepts it, and is idempotent for amend/transition
but NOT for create — a create op re-applied after a crashed remove would duplicate).
I argued the current order prevents that, but it's the liveliest piece and I could
not fully exercise it under concurrent sessions (outbox is per-session JSONL;
cross-session causal order is undefined — dossier-006 accepts brief outages, not
multi-writer, so this is within spec, but it's the edge I'd probe next).

## Gaps to flag

- **Reconcile create is not idempotent.** A create op re-applied (e.g. remove-ops
  crashed after a successful regista create) makes a duplicate regista work-item.
  The apply→remove→clear order makes this unlikely but not impossible. Mitigation
  is the `source_identifier` idempotency the migration already uses — reconcile's
  create path should check for an existing `source_identifier` before creating,
  like the migration does. (`core/reconcile.py` `_dispatch` create branch.)
- **Cross-session outbox ordering is undefined.** `read_all` sorts by
  `(session, client_seq)`; with two concurrent agents' session files, causal order
  across them isn't enforced. Within dossier-006's "brief outages, not a replica"
  scope, but worth noting if multi-writer ever becomes real.
- **`export-index` writes to repo root** without `git check-ignore` (WI-012) — the
  STALE banner could get committed. Medium.
- **The optional `TestE2EPostgres` skips** on the pg17 testcontainer (WI-010) — the
  one live-Postgres AC-1 test doesn't actually run; InMemory AC tests carry the gate.
- **D2 outbox signing key** lives at `~/.config/agent-notes/signing.key` (Ed25519,
  `LocalKeySigner`); generated on first use. If that key is lost, every pending
  outbox op fails signature verification at reconcile (rejected loudly, not applied).
  No rotation story yet — acceptable for a staging-area integrity stamp, but flag it.
- **`AGENT_NOTES_REGISTA_WRITES` is cached** in `face_factory.get_face()` after first
  build; flipping it requires a process restart. Fine for a controlled rollout, not
  for runtime toggling.

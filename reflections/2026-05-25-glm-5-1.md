# Session Reflection — 2026-05-25

**Work summary:** Performed a full adversarial code review of the entire repo — core, servers, CLI, web frontend, scripts, schema, and tests. Identified ~60 issues across security, correctness, robustness, dead code, inconsistency, test quality, and schema categories. Fixed 20 high/medium-severity bugs, all verified by the existing 220-test suite passing.

---

## On the project

The codebase is in solid shape architecturally — the decisions in Plan 001 are well-reasoned and mostly well-implemented. The Phase 9a CLI flattening is a clear improvement over per-kind MCP servers. The test coverage is good at the integration level (220 tests against real Postgres via testcontainers).

However, the code shows signs of having been built incrementally by multiple agents without a single cleanup pass. There are patterns that work correctly in one module and are subtly broken in another (e.g., `remove_link` checks `rowcount` before writing change_log, but `add_link` didn't). The import scripts feel particularly fragile — trigger-disable-without-finally is the kind of bug that only manifests when something goes wrong, making it invisible in normal testing.

The web frontend is the roughest part — async handlers doing blocking I/O is a textbook FastAPI mistake, and `SELECT *` leaking internal columns (embedding vectors!) to templates is a real data exposure risk. The fix to use explicit column lists and sync handlers is straightforward.

## On the work done

I'm confident in the fixes applied. Each one maps to a clear, demonstrable bug or security issue:

- **SQL injection in LISTEN** — used `psycopg.sql.Identifier` for safe quoting
- **Spurious link_added change_log** — now checks `rowcount` before writing audit entry
- **Path boundary false-match** — enforces separator between repo_root and query path
- **Error info leak** — generic exceptions now return `-32603` JSON-RPC errors, not successful responses with internal details
- **Thread-unsafe pool** — added double-checked locking matching the embed.py pattern
- **DSN at import time** — moved to lazy evaluation inside `_get_pool()`
- **Null derefs** — added guards in breadcrumb update (both server and CLI paths)
- **Raw string CLI args** — `--external-refs`, `--diagnostic-keys`, `--attributes` now parse JSON
- **Trigger safety** — all three import scripts now use `try/finally` around trigger disable
- **Async web routes** — changed to sync `def` so FastAPI dispatches to threadpool
- **SELECT \*** — replaced with explicit column list in `_get_breadcrumb`

Things I'd want a second pair of eyes on: the `_DSN` removal from `db.py` touches conftest.py, test_smoke_db.py, and both import scripts. The test suite passes but edge cases around pool initialization ordering in multi-process deployments deserve attention.

## Gaps to flag

- **`trust_remote_code=True` in embed.py:38** — if `AGENT_NOTES_EMBED_MODEL` is overridden to a malicious repo, arbitrary code execution. Should be documented as a security decision or pinned to a revision hash.
- **`import_legacy_bc.py` inserts breadcrumbs and change_log in separate transactions** (lines 266-272) — if change_log insert fails after breadcrumbs commit, audit trail is incomplete. Same pattern isn't present in the other two import scripts (they use one connection).
- **`import_legacy_memory.py` supersedes chain broken for out-of-order UUIDs** (line 94-134) — if memory A supersedes B and A's UUID sorts before B's, the link is silently lost. Two-pass import needed.
- **`import_reflections.py` writes change_log for skipped (ON CONFLICT DO NOTHING) rows** (lines 122, 155) — phantom audit entries for reflections that weren't actually imported.
- **`_search_all` in web/app.py sends embedding vector over the wire twice per query** (4x total for bc+memory) — should use subquery to compute distance once.
- **Test quality: all test embeddings are zero vectors** — similarity ranking is meaningless. Tests that depend on ranking (find, suggest_duplicates, search) are not meaningfully exercised.
- **No test for `BreadcrumbModel.delete_breadcrumb`** — a regression could silently break deletion.
- **No test for upsert behavior** — `file_breadcrumb` uses `ON CONFLICT DO UPDATE` but this is never tested.
- **No test for cross-project isolation** — model layer never verifies data doesn't leak between projects.
- **No test for `trace_graph` cycle detection** — recursive CTE relies solely on `max_depth` to terminate.
- **Schema `allocate_bc_identifier` has INSERT race** (lines 31-36 of 100_breadcrumbs.sql) — concurrent calls can hit PK violation.
- **`buffer.pop(0)` in bridge.py:135 is O(n)** — should use `collections.deque.popleft()`.
